4. Customer Due

Each customer has a continuously calculated outstanding balance.

For example:

Opening

Opening Balance = Rs. 20,000

Customer owes:

Rs. 20,000

Recovery

You receive:

Rs. 5,000

New balance:

20,000 - 5,000 = 15,000

The customer now shows:

Rs. 15,000

New Bill

Later you create a bill:

Bill = Rs. 50,000

New balance:

15,000 + 50,000 = 65,000

Customer now owes:

Rs. 65,000

So the basic accounting logic is:

New Balance = Previous Balance + Bill − Recovery

7. History

This is an important section.

Every financial transaction should be permanently recorded.

For example:

Recovery

Date	Customer	Booker	Type	Previous	Recovery	New Balance

28 Aug	Ahmed Store	Ahmed	Recovery	20,000	5,000	15,000


Bill

Date	Customer	Booker	Type	Previous	Bill	New Balance

28 Aug	Ahmed Store	Ahmed	Bill	15,000	50,000	65,000


The history should be transaction-based, meaning we don't simply overwrite the balance.

This is important because you can always see exactly what happened.

13. Database Structure

I would structure the SQLite database roughly like this:

database.db

├── customers
├── bookers
├── areas
├── cities
├── transactions
└── settings

The important part is that transactions are never simply deleted when the balance changes.

For example:

Opening Balance
       ↓
+ Bills
       ↓
- Recoveries
       ↓
Current Balance

This allows the application to maintain a proper financial history.

14. Data Protection & Transfer

Since this is a local application, I would keep the actual business data separate from the application installation.

Something like:

AlhamdTraders/
│
├── app
│   └── application files
│
└── data
    ├── alhamd.db
    ├── backups
    └── documents

The database can be backed up.

For example:

Alhamd_Backup_2026-08-28.db

Or a complete backup:

Alhamd_Backup_2026-08-28.zip

Then you can move it using a USB to another computer.

That gives you the behavior you originally described:

Old PC → Copy backup/data → New PC → Restore → All customers/history/settings return.

I would also strongly recommend an automatic backup system so a damaged database or accidental mistake doesn't destroy all business records.

Important behavior for Edit/Delete
I recommend that editing a transaction automatically recalculates all balances affected by that transaction, rather than permanently storing a manually entered "new balance."
For example:
Opening Balance                 Rs. 20,000

28 Aug — Bill                   +Rs. 50,000
29 Aug — Recovery               -Rs. 10,000
30 Aug — Bill                   +Rs. 15,000

Current Due                     Rs. 75,000
If you edit the 28 Aug bill from 50,000 → 40,000, the system recalculates:
20,000 + 40,000 - 10,000 + 15,000
= Rs. 65,000
Likewise, if you delete the recovery, the balance automatically becomes:
Rs. 75,000 + Rs. 10,000
= Rs. 85,000
This is much safer than simply modifying the current balance.
One other recommendation
For deletion, I would show a confirmation:
Delete this transaction?
Customer: Ahmed Store
Type: Recovery
Amount: Rs. 5,000
Date: 28 Aug 2026
Cancel | Delete
That prevents accidental deletion.
And because you're using one computer, we can also have automatic database backups, for example whenever the application starts or once per day. That way, if something goes wrong, you have a previous copy of the database.
